화면 3.5 — outline 검토 (새 단계)

0) 새 흐름

화면 3 (디자인) 와 화면 4 (슬라이드 만들기) 사이에 한 단계 추가됨.

① AI 도구→ ② 내용 올리기→ ③ 디자인→ ④ outline 검토 (NEW)→ ⑤ 슬라이드 만들기

1) 화면 3 의 [시작하기] 직후 — plan 작업 중

아직 outline 안 만들어진 상태. plan skill 만 호출 (보통 30초~2분).

발표 구조 잡는 중…
AI 가 어떤 슬라이드를 만들지 짧게 정리하고 있어요.

2) outline 도착 — 검토 / 편집 / 진행

frontmatter (yaml) + body 합쳐서 보여줌. 사용자가 텍스트 자체를 직접 수정 가능. 저장 따로 X — 편집한 내용이 [이대로 만들기] 누를 때 그대로 사용됨.

💡 frontmatter (가장 위 --- 사이) 의 style 만 손대지 마세요 — 화면 3 에서 고른 디자인 id 예요. 슬라이드 내용은 자유롭게.

3) 동작 메모

  • 화면 3 의 "시작하기" → 새 흐름: 곧바로 화면 4 (만들기) 가 아니라 화면 3.5 (outline 검토) 로.
  • plan 만 먼저 호출. AI 가 30초~2분 안에 outline 만들어 디스크 (`slide-outline.md`) 에 저장. 우리 앱이 그 파일 읽어 textarea 채움.
  • [이대로 만들기] 클릭 → 화면 4 로 이동 + design + validate 시작. textarea 내용이 그대로 outline.md 에 저장된 후 호출.
  • [← 디자인 다시] 클릭 → 화면 3 으로 돌아감. 디자인 다시 고르면 plan 도 처음부터 다시.
  • 편집 = 디스크 저장만 — outline.md 를 사용자 텍스트로 덮어쓰기. AI 한 번 더 호출 안 함. (자연어 조정 "표지 빼줘" 같은 건 다음 단계 후속.)
  • 새 status: draft → outlining → outline-ready → generating → ready. outline-ready 일 때만 이 화면 진입 가능.
  • 이전 deck 호환: outlining/outline-ready 단계 없이 generating 으로 바로 간 deck (현재 라이브러리의 모든 deck) 은 그대로 표시. 새 deck 부터 적용.
